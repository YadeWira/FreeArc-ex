# Compatibility and verification

## What is promised

| area | commitment |
|---|---|
| `.arc` format | read and write any archive that FreeArc 0.67.1 reads/writes, including encryption, recovery record, solid blocks and SFX |
| CLI | same options, same semantics and same exit codes as `arc.exe` 0.67.1 |
| `arc.ini` + Lua | configuration and events with Lua 5.1, existing scripts unchanged |
| status | methods table read from `arc.ini` (`-cfg` selects the file); `arc.*.lua` event hooks implemented (Program/Command/Archive Start/Done, Error, Warning) |
| SFX / `unarc.dll` | self-extracting modules and the callback DLL, Windows only |
| Explorer | COM context menu (x86 and x64) and file associations, Windows only |
| Containers | reading `.7z`/`.zip`/`.rar` (writing `.zip` if agreed) |
| Platforms | Linux x86_64/i686/aarch64; Windows x86_64/i686 with Windows 7 SP1 as the minimum |
| GUI | GTK3 via gtkmm 3.24, optional build (`FA_BUILD_GUI`); first slice lists archives |

## How it is verified: the oracle

Every engine change is compared against the original binary, never against our
own expectations:

- **Oracle**: `Arc.exe` 0.67.1 under wine, plus the `unarc` unpacker as the
  extraction authority. FreeArc-ex keeps its own copies so the tests do not
  depend on another project's workspace:
  - `/mnt/IA_LAB/agentes/arc/bin/Arc.exe`
    sha256 `1b23732e158540eb159563b557ab1d396b12cd56178ea9387e696d054d3e2172`,
    reports `FreeArc 0.67.1 (March 07 2021)` (krinkels.org build)
  - `/mnt/IA_LAB/agentes/arc/bin/unarc.i386`
    sha256 `67e20bee81c1cac87438d0f1d8e76127c0d6df354f47fcec94a7c87c8d3d2377`,
    `FreeArc 0.67 unpacker 2014-03-16`
  - `/mnt/IA_LAB/agentes/arc/bin/unarc.x64`
    sha256 `d25cfd4939be4f7843f2418b1e0ccd7abcf2ab11028d04954f985df93d475853`
  - Check: `scripts/oracle-smoke.sh` (runs a/t/x plus an `unarc` test)
  - Overrides: `FA_ARC_ORACLE`, `FA_UNARC`
- **Direction 1**: what `arc-ex` writes is listed, tested and extracted by
  `arc.exe` (plus `unarc` from 0.67 for the SFX extraction path).
- **Direction 2**: what `arc.exe` writes is read by `arc-ex`, with an identical
  extracted tree (compared by hash and by permissions/dates).
- **Structure**: comparison of the archive blocks (types, methods, sizes,
  offsets) against the reference reader; an archive may differ byte by byte and
  still be valid, but the structure must match when the method is the same.

## Corpus

See `tests/corpus/README.md`. Test files are **not** stored in the repository:
they are generated by `tests/corpus/make-corpus.sh`. For material from the shared
corpus (`/mnt/OSR_D3/fileFormatSamples`), always copy, never work in place.

Cases the corpus must cover: text, binaries, already-compressed data, random data,
a file above 4 GiB, UTF-8 names, paths over 260 characters (Windows), empty
directories, files with permissions and extreme dates (1970, 2038), and 0-byte
files.

## Current limitations (M2, in progress)

- **Methods**: the whole legacy engine is linked in, so `lzma`, `rep`, `4x4`,
  `tor`, `dict`, `lzp`, `grzip`, `tta`, `mm`, `delta`, `exe`, `dispack070` and
  arbitrary chains of them (`rep:96m+lzma:8mb`, `exe+lzma:16mb`, ...) work in
  both directions.
- **Known gap**: `lz4` (the 2012 codec rejects real blocks with error -7) is
  rejected on all architectures; the 1.10 decoder comes with the library update.
  Everything else, including `ppmd` on 64-bit (32-bit heap layout emulated), is
  supported and verified against `arc.exe`.
- **Presets**: `-m0`..`-m9` resolve through FreeArc's own definition table
  (built-in, or `arc.ini` if present) and the file classes in `arc.groups`;
  files are grouped into one solid block per resolved method and dictionaries are
  limited to the block size. Binary presets work end to end. **Text presets
  (4t/5t and above) are blocked by PPMd**, so a tree with `.txt` files currently
  stops with a clear error instead of writing a wrong archive.
- **Solid blocks**: `-s` (all together), `-s-` (one file per block), `-s<N>f`
  (by count), `-s<SIZE>` (`k`/`m`/`g`), `-se` (by extension) and combinations
  such as `-se10f1m`. Directories always go to their own storing block, as the
  original does. Block structure matches `arc.exe` for the tested options
  (`tests/integration/solid.sh`).
- **Encryption**: `-p<password>` encrypts the data blocks (AES-256/CTR, 1000
  PBKDF2 iterations), and the same option decrypts; wrong passwords are detected
  through the stored check-code before decrypting. Interoperability verified in
  both directions with `arc.exe`. `-hp` additionally encrypts the header and the
  directory (each control block with its own salt/IV; the footer stays readable),
  so even listing requires the password; verified in both directions.
- **Recovery record**: `-rr` writes the rotating-XOR parity record plus the
  sector CRCs (two `RECOVERY_BLOCK`s after a provisional footer, then the
  definitive footer), with FreeArc's parameter derivation (`-rr4%`, `-rr1m`,
  `-rr10`, `-rr8*4096`, `-rr3%;4096`). `arc.exe` reports the record, tests the
  archive and repairs a damaged sector with it. Our own `r` (repair) is not
  implemented yet: `t` reports the CRC mismatch.
- Commands: `a`, `u`, `f`, `d`, `l`, `lb`, `t`, `x`. Update **reuses the blocks
  whose files are all unchanged** (they are copied verbatim, compressed bytes
  included) and recompresses only the affected ones; blocks that gain or lose
  files are rebuilt. This matches the original's intent, not yet its exact
  layout in every case (its block-reuse heuristics are more elaborate). No masks
  or selective extraction, no overwrite policy.
- Creation writes a single solid data block and stores the directory
  uncompressed; splitting and `-dm` methods arrive later in M2.
- Reading is memory-mapped; creation still reads each file into memory, so very
  large inputs are limited by available RAM.

## What is NOT promised

- Writing `.arc` files with byte-identical methods (the format allows any valid
  stream; structure and readability are the requirement, not byte equality).
- Running on Windows XP/Vista, or on Linux with glibc older than Debian 12.
- Reading `.parc` (PArc's own format; different project).
