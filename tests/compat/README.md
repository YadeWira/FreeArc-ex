# Compatibility harness

Differential tests that compare FreeArc-ex against the original binary. This is
the mechanism ADR [0002](../../docs/adr/0002-compatibility-oracle.md) makes
mandatory: no feature is declared compatible without passing it.

## Status

`vendor/` holds the .arc test suite written by the **PArc** project (a separate
Free Pascal rewrite of FreeArc 0.67). It was handed over on 2026-10-20 at tag
`entrega-arc` (commit `56b63de`) and is stored **unmodified** for reference.
Its comments are in Spanish and it drives PArc's binary, so it is not runnable
as-is: the adaptation to `arc-ex` happens incrementally as the engine grows
(M1 onwards), and each adapted test moves out of `vendor/` into this directory.

| file | what it checks | FreeArc-ex milestone |
|---|---|---|
| `canon_methods.sh` | the stored method text matches `arc.exe` | M2 |
| `order_matrix.sh` | solid block splitting and ordering matches `arc.exe` | M2 |
| `write_matrix.sh` | archives written by us are tested and extracted by `arc.exe`/`unarc` | M1, M2 |
| `update_matrix.sh` | `a/u/f/d` semantics match the binary | M2 |
| `compat_matrix.sh` | reading of every method, with its own deterministic corpus | M1, M2 |
| `regress.sh` | extraction compared against `unarc` | M1 |
| `fuzz_update.py` | random update sequences compared with `arc.exe` | M2 |
| `containers.sh` | `.zip`/`.7z`/`.rar` via an external 7-Zip binary | M6 |
| `BUGS-FREEARC.md` | bug survey of 0.67 (severity, reproduction, evidence) | reference |

## Data they need

Nothing of this is versioned; it is regenerated or copied:

- `compat_matrix.sh` builds its own deterministic corpus (~149 MB; over 2 GB with
  `--big`). `order_matrix.sh` and `write_matrix.sh` reuse it, so run
  `compat_matrix.sh` first.
- `regress.sh` expects `/mnt/IA_LAB/compartido/parc/samples/gen` (105 MB of `.arc`
  files produced by `arc.exe`, each with its `.cmd.txt`) and `samples/src`
  (9.5 MB). They are regenerated by replaying the `.cmd.txt` files.
- Oracle: `arc.exe` 0.67.1 under a wine prefix (see `docs/COMPAT.md`).

## Adaptation rules

When a script is adapted it must:

1. Name the binary under test through `SUT` (default `./build/linux-x64/src/cli/arc-ex`),
   never the old `parc` default, and take the oracle from `FA_ARC_ORACLE`.
2. Work in `IA_LAB` under this agent's own folder, not PArc's.
3. Drop `.parc`-specific steps: FreeArc-ex does not read or write `.parc`.
4. Be translated to English, keeping the original logic and the reference to the
   upstream script it came from.
